### Le pont Brain est implémenté, pas seulement spécifié

`.kiro/specs/brain-cms-bridge/` (7 tâches cochées / 3 restantes) décrit un pont
HTTP : le Brain **poll** le CMS toutes les 30 s (il est derrière un NAT, on ne
peut pas l'appeler). Routes réelles sous `app/api/brain/` :

| Route | Rôle |
|---|---|
| `POST /api/brain/tasks` | dépose (`agent: 'heldonica-brain'`, `status: 'sent'`) |
| `GET /api/brain/tasks?status=sent` | le poller lit |
| `PATCH /api/brain/tasks/[id]` | prise atomique (`eq status='sent'`) puis compte rendu |
| `GET /api/brain/status` + `POST /api/brain/heartbeat` | santé |

- Auth : `lib/bridge-auth.ts` — `x-cms-auth` (admin) **ou**
  `Authorization: Bearer $BRAIN_BRIDGE_TOKEN` (constant-time).
- Santé : `site_settings` clé **`brain_heartbeat`**, JSON
  `{last_seen, cpu_percent, ram_percent, ollama_running, active_model}` ;
  `online` = `last_seen` < **120 s**.
- **Il sait répondre** : ses 4 derniers `chat` sont `done`, la réponse est dans
  **`actions_done.result`** (pas dans `notes`).
- Dernier heartbeat vu : **2026-10-15T20:20:28Z**, `openai/gpt-oss-120b`,
  CPU 17 %, RAM 70 %, `ollama_running: false`. Dernière tâche traitée : 25/09.

### Cause racine trouvée : le Brain n'était pas adressable

Deux trous réels dans `mcp/agent-tasks/server.mjs` :
1. `AGENTS_CONNUS` listait 7 destinataires **sans** `heldonica-brain` ;
2. `deposer_tache` n'écrivait **ni `task_type` ni `payload`** — or le poller
   **dispatche sur `task_type`** et lit `payload.message`. Une tâche déposée par
   ce chemin aurait été **dépilée puis ignorée en silence**.

Corrigé sur la branche `agent/openhands/pont-brain-mcp` (commit `fb7fc68`) :
`heldonica-brain` ajouté ; `task_type`/`payload` exposés ; **garde** refusant une
tâche destinée au Brain sans `task_type` (ou `chat` sans `payload.message`) ;
section « Parler au Brain » dans le README du MCP.

### Vérification effectuée — et ce qui ne l'est pas

- `node --check` : OK.
- Essai MCP **en lecture seule** (fichier temporaire, supprimé) : **8/8**. Les 5
  outils restent exposés, les refus attendus se déclenchent, et le contrôle final
  compte **0 ligne écrite** dans `agent_tasks`.
- `npm run garde-fous` : **12/12**.
- **Non vérifié** : le trajet de bout en bout (dépôt réel → réponse du Brain), qui
  exige une écriture en base. Le harnais livré `test-client.mjs` **écrit et
  supprime** dans la table de production : ne pas le lancer sans accord.

### Pièges rencontrés

- `mcp/agent-tasks/node_modules` **absent** : `npm install` requis (94 paquets).
- **`.env.local` n'a pas `SUPABASE_SERVICE_ROLE_KEY`** : le serveur MCP ne peut pas
  démarrer depuis ce fichier seul — il faut la lui passer par l'environnement.
- Le `heredoc` bash est mal découpé par ce runtime quand il contient plusieurs
  commandes : préférer l'éditeur de fichiers ou un `python3 - <<'PY'` unique.
- `git diff` sur un fichier à caractères Unicode (tirets cadratins) : les ancres
  `old_str` à indentation exacte échouent ; passer par Python.
- `curl` sur `site_settings` avec `key=like.*brain*` : **`?key=eq.…` marche, mais
  `?or=(...)` et `?status=in_progress` exigent `eq.`** — PostgREST renvoie
  `PGRST100` sinon.
