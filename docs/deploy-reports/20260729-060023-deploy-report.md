1. **CI locale** : `npm install`, `npm run lint`, `npx tsc --noEmit`, `npm run build` — tous verts.

3. **PR #452** créée avec labels `audit-fixes`, `needs-migration`, `needs-content-review`.

5. **Merge confirmé** après build + typecheck + vérification manuelle en navigateur (page Madère, section B2B home).
6. **PR mergée** dans `main` (fast-forward, 208 fichiers).
7. **Déploiement production** : `vercel deploy --prod` → alias `www.heldonica.fr`.

## Régression détectée et corrigée post-déploiement

Le premier déploiement production contenait une régression silencieuse : `app/robots.ts` n'était pas dans la liste des 8 fichiers en conflit (donc auto-mergé sans avertissement), mais un commit concurrent sur `main` y avait réintroduit `Disallow: /expert-hotelier` — annulant directement le correctif H-01. Détecté par les vérifications post-déploiement ci-dessous, corrigé en commit séparé (`544775f`), rebuild et redéploiement production immédiat.

**Leçon** : un merge propre (0 conflit) ne garantit pas l'absence de régression quand du travail concurrent modifie la même fonctionnalité dans un fichier que l'une des deux branches n'a pas touché. Les vérifications post-déploiement fonctionnelles (pas seulement build/typecheck) restent nécessaires même après un merge "propre".
